# 設計:簽核會簽 / 或簽(D95,已實作)

## 目標與範圍
- 目前每一層只能指定**一個角色**,該角色任一人核准即過(等同「或簽」,但只有單一角色)。
- 本次讓**一層可指定多個角色**,並選擇該層的簽法:
  - **或簽**:任一角色的任一人核准,該層即通過。
  - **會簽**:每個指定角色都要各有一人核准,該層才通過。
- 不做:依部門 / 業務分流、同一角色要 N 人簽、動態加簽、逾時自動升級。

## 規則模型
- 第 1 層仍固定為「具該單據核准權限的人」,不可設多角色(維持舊行為)。
- 第 2~5 層每層:`roles`(1~5 個角色)+ `mode`(`any` 或 `all`)。只有 1 個角色時兩者等價,預設 `any`,所以**既有規則資料不用改語意**。
- 驗證:角色不可在同一層重複;會簽至少 2 個角色;每個角色都要具備該單據核准權限(同現行檢查);角色不可跨層重複沒有必要限制,但同一人跨層仍受「同人不可核准兩層」限制。

## 資料表(migration 000037)
- `approval_rule_steps`:新增 `mode VARCHAR(3) NOT NULL DEFAULT 'any'`(`any`/`all`);主鍵改 `(rule_id, step_no, role_id)`;同一 `step_no` 的 `mode` 一致由應用層保證(寫入時整層覆寫)。
- `document_approvals`:一層可有多列(每個角色一列,稱「簽核格」)。新增 `mode`;唯一鍵由 `(doc_type, doc_id, step_no)` 改為 `(doc_type, doc_id, step_no, slot_no)`,`slot_no` 從 1 起算。第 1 層固定 `slot_no = 1`。
- 送審時快照(沿用 D61):整張規則展開成簽核格,之後改規則不影響進行中單據。

## 引擎行為(`internal/approval`)
- 「目前層」= 第一個尚未通過的層。層通過條件:`any` → 有任一格已核准;`all` → 所有格已核准。
- 核准時:
  1. 在目前層找「我能負責且尚未核准」的格(本人或代理中的委託人具該角色;超級管理員可填任一空格);
  2. 找不到 → `APR-001`(訊息列出該層還缺的角色);
  3. 我在此單據已核准過任何格(含其他層)→ `APR-002`(一人一票,會簽也不能一人簽兩格);
  4. 若同時有多格可填,優先填**僅此角色能填**的格(避免一人兼兩角色時佔掉別人的格)。
  5. 層通過且還有後續層 → 回 partial,通知下一層所有角色;層未通過(會簽還缺人)→ 回 partial,訊息「第 n 層會簽:已 x/y,尚缺〈角色〉」。
- 或簽層通過後,同層其餘未簽的格視為免簽(保留在進度顯示為「免簽」,不再接受核准)。
- 退回 / 取消核准 / 作廢:照舊整張清除。

## 周邊影響
- **待我核准收件匣(D84)**:目前層若是會簽,只要我具備「尚未核准的格」的角色且我沒簽過就顯示;或簽層我具備任一角色即顯示。
- **通知(D88)**:進入某層時通知該層所有角色的成員(去重、不含本人)。
- **進度元件**:每層顯示各格(角色、核准人、時間、代理),層標示「或簽 / 會簽」,會簽顯示 x/y。
- **規則維護畫面**:每層可複選多個角色,多於 1 個時出現「或簽 / 會簽」選項。
- **API**:`ruleInput.role_ids` 改為 `steps: [{role_ids: [], mode}]`(第 2 層起);回傳 `steps` 同結構。前端與測試一併調整,舊格式不保留(內部系統,無外部呼叫端)。
- **稽核**:每次核准記稽核,內容增加層別與格號。

## 取捨與風險
- 角色被刪除時,該格 `role_id` 變 NULL:或簽層其他角色仍可用;會簽層該格只有超級管理員能填,且因一人一票,超級管理員若已簽過其他格就會卡住 → 規則維護畫面已禁止刪除被規則使用的角色(D61),風險低,維持現狀。
- 代理核准(D87)沿用:代理人填入委託人所屬角色的格,記 `acting_for`;一人一票以「本人 + 委託人」雙方是否已簽判斷(現行邏輯)。
- 會簽層沒簽完前單據一直待審,沒有逾時機制(本次不做)。
